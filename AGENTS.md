# Project instructions

## Production deployment by default

CJ's standing instruction for Hire Line Dancers, October 27, 2026: a request
to change this project authorizes implementing and shipping the requested scope
to production. Complete the necessary website deployment, GitHub updates,
production database migrations, backend function deployments, and verification
without asking for a separate release approval.

Preserve concurrent project work and verify the complete release against the
current live baseline. Respect an explicit request to plan, review, or keep a
change local. This standing instruction does not authorize unrelated scope,
materially destructive actions, spending, credential changes, external
communications, or unapproved creative content.

## Content authority

Implementation authority is not creative authority. Do not invent, embellish,
or infer user-facing copy, personal or biographical claims, first-person
language, marketing language, humor, captions, or brand statements unless CJ
explicitly requests writing or creative work in the current request. Project
style, brand, realism, polish, and production guidance applies only to content
CJ authorized; it never grants permission to create content. Omit missing
optional copy and ask for required wording. Before committing or deploying,
audit all changed user-facing strings across the complete release candidate
against the last approved or deployed baseline. Use the
`content-provenance-gate` skill when available; any unclassified string blocks
completion or release. A deploy request never approves undisclosed
agent-authored wording.

## Content style

- Never use em dashes in website copy, documentation, outreach, or any other written content.
- Rewrite the sentence with commas, periods, colons, parentheses, or semicolons instead.
